## Run the backend (A1)
```bash
# 1. Database (needs Docker)
docker compose up -d

# 2. Backend deps
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 3. Config
cp ../.env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"   # paste into JWT_SECRET in .env

# 4. Create tables (first time: generate the initial migration, then apply it)
alembic revision --autogenerate -m "initial schema"
alembic upgrade head

# 5. Demo data, then start the API
python seed.py
uvicorn app.main:app --reload
```
API docs: http://localhost:8000/docs

## Upgrading from A1/A2 to B
```bash
cd backend
pip install -r requirements.txt            # adds pypdf, python-docx, python-pptx
alembic revision --autogenerate -m "initial schema"   # only if you have not created tables yet
alembic upgrade head
```
Batch B changes no table definitions, so an existing A1 database needs no new migration.
Faculty flow: sign in as admin -> Copyright Undertaking -> Upload Material -> Knowledge Base.

## Batch C: enabling the AI
1. `pip install -r requirements.txt` (adds `sentence-transformers`; it pulls in PyTorch, ~2 GB. For a quick demo
   without it, set `EMBEDDING_PROVIDER=hashing` - keyword-level search only).
2. Get a free Gemini key at https://aistudio.google.com/apikey and put it in `backend/.env` as `GEMINI_API_KEY=...`
   (or choose `LLM_PROVIDER=ollama|openai|anthropic` - see `.env.example`).
3. Restart the backend. **Documents uploaded in Batch B stop at "Chunked (needs re-index)"** - open
   Admin -> Knowledge Base and click the re-index icon on each; they become "Indexed".
4. Student -> Ask AI -> pick a subject -> ask a question about your uploaded material.

If you change `EMBEDDING_MODEL` to one with a different vector size, the database column (384) must change too.

## Batch D1: student features
- Dashboard, My Doubts (search/filter/open/delete), Subjects (units), Notes (download), Search, Quizzes, Progress.
- Quizzes are generated by the LLM **only from retrieved passages**, validated server-side (4 distinct options, one
  correct, valid source) and the answer key is never sent to the browser before submission.
- Weak-topic labels come from simple, explainable rules (`backend/app/services/topic_status.py`).
- Students can download the original file of material from **their own department** (authenticated; served as an
  attachment with `nosniff`). Remove `/documents/{id}/download` if your college doesn't want file distribution.
- Activity streak is counted in UTC days.

## Batch D2: admin features
- **Dashboard**: all numbers are live database counts (the prototype's demo values are gone).
- **Student doubts**: aggregated and anonymised. Frequent concepts appear only when >= 2 different students asked
  (`MIN_STUDENTS_FOR_CONCEPTS` in `backend/app/services/admin_service.py`). Unanswered questions are listed without any
  student identity and grouped when several students ask the same thing.
- **Analytics**: doubts/day, uploads/day, knowledge-base growth, top subjects/topics, quiz performance, active students
  (charts use Recharts - run `npm install` again).
- **Knowledge base**: filter/search, re-index, archive/restore (archived = not used by the AI or shown to students, but
  kept), delete (removes files + passages), per-version download and "Make live" rollback.
